## What changed

- `/api/books/{id}/stream` returns **410** to every authenticated caller, including purchasers and admins. There is no full-file fallback for older clients.
- Both free and paid library books must use private `book-files` storage. Uploading PDF/EPUB as a public asset is rejected. New protected book editions must be PDF; existing EPUBs need a PDF edition and fail closed in this reader.
- The backend renders one JPEG page at a time with a repeated server-side user/session watermark. It does not return the source PDF, a source storage URL, a PDF blob, or a downloadable PDF cache. The footer is added outside the original page content.
- Reading requires a Google-verified Play Integrity verdict: correct package, approved app-signing certificate, version code 10 or later, `PLAY_RECOGNIZED`, `LICENSED`, `MEETS_DEVICE_INTEGRITY`, and an available App access risk verdict without capture/control/overlay risks.
- A single-use 90-second challenge binds attestation to this user, book and device public key. Sessions expire after five minutes; a new session replaces the account's previous session. The app re-verifies periodically and after returning to the foreground.
- Every page request checks purchase access again and needs a short-lived ECDSA signature from the Android Keystore key, bound to the book, session, page, timestamp and nonce. Used nonces cannot be replayed. No static signing secret is shipped in the app.
- Page requests are limited to 30/minute per account; challenges and activation attempts are each limited to 6/minute. Rendering is serialized per server instance, with 50 MiB source, 2,000-page and page-dimension limits.
- The Android window uses `FLAG_SECURE`, hides overlays on supported Android versions, and disables recent-task screenshots. The app hides/evicts page images on backgrounding. Backups/device transfer and cleartext HTTP are disabled.
- Access/refresh tokens migrate from plaintext Flutter preferences to encrypted secure storage. Release builds use R8/resource shrinking and Dart obfuscation. Debug/profile readers deliberately refuse to open protected books.
- Website purchases remain available when Razorpay is configured. Website book downloads/browser reading were removed; buyers read with the same account in the Android app. Browsers cannot provide the Android capture protections.

## Security boundary

Original library PDFs can be kept server-side, and normal supported Android screenshot/recording paths can be blocked. **Even excluding another phone's camera, zero-copy protection against a fully compromised OS or instrumented genuine process cannot be guaranteed.** Displayed page pixels must exist on the device; a sufficiently privileged attacker may capture/reconstruct watermarked images. Play Integrity, device keys, short sessions and watermarks raise the cost and help trace leaks; they do not establish a mathematical guarantee of non-extraction.

The source-PDF protection applies to the library book API. External websites, videos, or separately published course/material links have their own access controls and are not turned into protected library books automatically.
